# 2026-07-06 工作日誌

## dev_pub_0.9 外網部署架構設計（設計階段，未動程式碼）

### 需求（使用者原話拆解）
針對 `dev_pub_0.9` 分支（外網使用）：
1. 修改所有內部 gRPC 的行為，只對 agent_gateway 回應
2. 修改 agent_client，僅使用 gRPC 連接 agent_gateway
3. 加上 API Key 認證，一個 API Key 只能用在一個設備上
先設計、記錄在 CLAUDE.md，晚些佈署在測試 Linux 服務器。

### 設計結論（完整版見根 CLAUDE.md「dev_pub_0.9 外網部署架構設計」節）

**現況盤點**：client 目前直連三個服務（agents `:18080` REST、agent_graph `:8504` REST、agent_embedding `:8502` REST，最後一個是今天 §3.3 Verify 才加的）；gateway 只有 A2A JSON-RPC（`:8090`）與 `AgentService.Inbound` 轉發（`:9090`），**沒有**涵蓋 client 需要的同步對話/上傳/圖譜查詢語意——所以這不是「把 URL 改掉」而是要新建一整層 client-facing gRPC 契約。

**關鍵設計決策與理由**：

1. **新 proto `ClientGateway`（gateway 對外唯一介面）**：`Ping`/`Chat`/`UploadIngest`（client-streaming，≤64KB chunk 邊收邊轉）/`GetIngestJob`/`Graph*` 5 支/`VerifySearch`。
   - `Chat` 需要 agents 端配套新增 gRPC `AgentService.Chat`（薄包裝既有 `ChatSync`，不動業務邏輯）——選這個而非 gateway 內部轉 REST，少一次 JSON/TLS 開銷、契約也更明確。
   - `agent_graph` 需補 3 個 proposed-review RPC。**注意語意矯正**：昨天記錄「gRPC 刻意不加（不給 LLM 工具用）」——這次加進 `GraphService` 但 `agents` 的 `graph_query` 工具不包它們，LLM 工具面不變；「不給 LLM 用」的真正邊界是工具註冊面，不是 proto 面。
   - `agent_embedding` 是唯一不加 gRPC 的服務：只有一個輕量 Verify 查詢，為它建整套 proto/pb 不划算，gateway 內部走 HTTPS REST（綁內網）。

2. **「內部 gRPC 只對 gateway 回應」的正確解讀**：不能字面照做——`agent_memory`/`agent_critic` 的合法呼叫端是 `agents` 不是 gateway，字面實作會弄壞內部鏈路。實際設計是 **mTLS + per-service CN 允許清單**：gencert 擴充成兩段式（內部 CA → 簽發各服務 server/client cert，client cert CN=服務名），每個內部 gRPC server 開 `RequireAndVerifyClientCert` + interceptor 比對允許清單（agents←gateway；memory/critic←agents；graph←agents+gateway）。允許清單放 config，空清單=拒絕全部（安全預設）。gateway 對外 `:9090` 不用 mTLS（外部 client 無法安全持有內部憑證），靠 API Key。部署層第二道防線：內部服務全部 bind 內網/localhost，防火牆只開 `:9090`。

3. **API Key 一 Key 一裝置**：gateway 從「無狀態」改掛 PG（hidb，沿用 .201），新表 `api_keys`（只存 SHA-256 hash，明文不落地）。綁定用 **TOFU（首用即綁）**：metadata 帶 `x-api-key`+`x-device-id`，首次使用以 `UPDATE ... WHERE device_id IS NULL` 原子綁定（防多裝置搶綁競態），不符回 `PermissionDenied`。Key 管理走 admin CLI（`gateway apikey create/list/revoke/unbind`，只能在部署機執行，明文只印一次）。client 端 device_id = SHA-256(Windows MachineGuid + username)，穩定且不含明文 PII。

4. **client 改動**：三個 REST client（`APIClient`/`GraphClient`/`EmbeddingClient`）→ 單一 `GatewayClient`（gRPC）；Config 三個 URL → `GatewayAddr`+`APIKey`；設定頁對應簡化；`InsecureTLS` 測試期保留，正式改 CA pinning（隨附 `gateway-ca.pem`）。

5. **Linux 部署**：7 個 systemd unit；只有 gateway `:9090` 對外（`:8090` A2A 公網版關閉或限內網）；後端純 Go 可 `GOOS=linux` 交叉編譯，client 仍為 Windows 桌面程式。

**實作順序**（寫進 CLAUDE.md §6）：gencert/mTLS → agents+graph 新 RPC → gateway（proto/轉發/PG/auth/CLI）→ client GatewayClient → 部署腳本與端到端。

**未決事項**（不阻塞開工）：多副本 gateway 的 last_used_at 寫入放大、key 輪替（第一版只有 revoke）、上傳大小上限/限流、agent_registry 是否進 mTLS 圈（第一版不動，靠內網綁定）。
