## 三、pub_client 知識圖譜分頁：改成 Obsidian graph view 風格

使用者要求「把 Obsidian vault 的視覺效果整合到 client 端的知識圖譜」。先做研究再實作。

### 研究（WebFetch）

Obsidian graph view 的視覺特徵：
- **節點大小** ∝ 被引用次數（degree）；**線** = 內部連結
- **Filters**：檔案 / 標籤 / 附件 / 孤兒
- **Groups**：搜尋條件染色（顏色識別）
- **Display**：箭頭、文字透明度、節點大小、連線粗細、時間軸動畫
- **Forces**：中心力 / 排斥力 / 連結力 / 連結距離（force-directed 物理即時可調）
- **Local vs Global**：全域圖譜 vs 當前筆記 N-hop 鄰域

### 現況盤點（Explore agent）

- `pub_client/app/views/graph_view.go:graphCanvas()` 是「中心 + 環狀 16 鄰居靜態放射狀」（`widget.Button` 節點 + `canvas.Line` 邊，固定 680×460 畫布），無物理、無拖曳、無 zoom/pan。
- backend 節點只有 `name/category/description/source_file/score`，**沒有 id、沒有 degree**；沒有 dump-all endpoint（只有 `GetLocalContext(hops, limit)`）。
- go.mod 無任何 force-directed 套件。

### 實作決策

**MVP 只動 pub_client 端**（不動 proto/gateway/graph）：
- 自訂 Fyne widget，用 `canvas.Circle / canvas.Text / canvas.Line` 手繪
- Coulomb 斥力 + Hooke 彈簧 + 向心力，30fps ticker
- Degree 由 client 從當前 subgraph 邊清單即時算（backend 沒回）
- Category hash → HSL hue 決定節點顏色；中心用 `theme.PrimaryColor()`
- 深/淺主題自動適配（每次 Refresh 重讀 `theme.BackgroundColor/ForegroundColor/DisabledColor`）
- 拖曳節點（`fyne.Draggable`，拖曳中 `pinned=true` 固定位置）
- 空白處拖曳 = pan；滾輪 zoom（以游標為錨點，符合 Obsidian 行為）
- 點擊節點觸發 `loadContext(name)`（沿用既有搜尋鏈路）
- Sidebar：Fit / Reset 兩顆按鈕 + Repel/Spring/Distance 三條 slider（Obsidian Forces 面板小巧版）

**先不做**（scope 控制，等 MVP 驗證後再擴充）：
- 全 vault overview（需新 backend endpoint `GraphOverview`，proto/gateway/graph 三邊改）
- 搜尋式群組染色（Obsidian Groups 面板）
- 時間軸動畫、Filter 面板

### 檔案變更

| 檔 | 動作 | 內容 |
|---|---|---|
| `pub_client/app/views/graph_widget.go` | **新增**（~440 行） | `graphWidget`（`widget.BaseWidget` + Draggable/Scrollable/Mouseable）+ `graphRenderer` + 物理 sim goroutine + hitTest + HSL 顏色 helper + 編譯期介面斷言 |
| `pub_client/app/views/graph_view.go` | 改 | `graphExploreView` 用常駐 `gw := newGraphWidget(...)` + `showContext` 呼叫 `gw.SetContext(...)`；上方加 Fit/Reset/3-slider 控制列；刪除舊 `graphCanvas` 函式 + 相關 import（`canvas`、`math`、`theme` 已不用）|

### 踩坑 / 注意

- `Circle.Position1/Position2` 是 bbox 頂點但 Move/Resize 也生效，用哪個都行。
- `fyne.Scrollable` 在 `fyne` 套件不是 `desktop`（wheel 事件走這個 interface）；`desktop.Mouseable` 才在 `desktop`。加了編譯期斷言 `var _ fyne.Draggable = ...` 讓 typo 在 build 時炸。
- Sim goroutine 用 stopOnce 保護 stop channel 關閉；動能低於門檻 3 tick 後停送 Refresh 省 CPU（拖曳時視為「還在動」持續送）。
- `SetContext` 保留 pan/zoom（跳到相鄰實體時視角不重置，比較不暈）；`ResetLayout` 才把視角歸零並重灑位置。
- 初始位置用 `fnv1a(centerName)` 作 seed 的隨機環狀擺放——同一實體反覆載入時佈局穩定。
- Renderer 的 primitives slice 在 SetContext 節點/邊數變動時 rebuild；`Objects()` 每次呼叫都會檢查 `lastNodes`/`lastEdges` 觸發 rebuild（Fyne driver 每次 paint 都查 Objects 應能拿到新的 primitives）。
- `graphHint`（"Search and select..." 提示 label）用 `container.NewStack(gw, graphHint)` 疊在 widget 上，`showContext` 首次呼叫時 `Hide()`；之後就永久隱藏。

### 驗證

- `go build ./... && go vet ./... && go test ./...` — 全綠（`app/services` + `app/store` + `app/models` 測試 pass，views 無 test file 是既有狀況）。
- Fyne UI 本身無法在無頭環境驗證（CLAUDE.md 既有限制第 4 條）——實機視覺驗證（拖曳流暢度、zoom 錨點正確性、深/淺主題切換）由使用者做。

## 四、Vault 鏡像三部曲：圖譜→vault .md、client Sync Vault 下載、搜尋關鍵節點

使用者三點需求：(1) 建立圖譜時同時建立 vault 的 md 文件、每次建立檢查最近更動並同步；
(2) client 端 sync 時下載 md 到使用者 PC；(3) 搜尋時尋找最接近搜尋結果的關鍵節點。
橫跨 agent_graph / agent_gateway / pub_client 三個 module（+ pb 複製到 rag_admin）。

### (1) agent_graph：VaultExporter（圖譜 → vault 鏡像）

- **新檔 `app/services/vault_export.go`**：每個 Entity 節點 render 成
  `<vault>/entities/<sanitized-name>.md`——frontmatter（aliases/category/tags: kb/<cat>/source）
  + 描述 + 出向關係的 `[[wikilink]]`（type 附註）。**render 是確定性的**（關係排序、無時間戳），
  增量比對靠 bytes.Equal，內容沒變不落盤。
- **檔名 sanitize**（`entityFileBase`）：Windows 保留字元 + Obsidian wikilink 語法字元（`#^[]|`）
  換 `_`；被改動過的名稱附 sha256 前 4 bytes 後綴防撞（"a/b" vs "a:b"）；wikilink 一律用
  fileBase、原名走 `aliases:` + `[[fileBase|原名]]`——Obsidian 圖譜才不會出現 ghost node。
- **同步語意**：facade 四個寫入點（UpsertEntityDirect/UpsertRelationDirect/ApproveProposed/
  IngestText）+ sync worker 的 SyncFile/applyExtraction 成功後 `Notify(受影響實體...)`；
  exporter 背景迴圈 debounce 2s 批次匯出；啟動時 `NotifyAll()` 全量 reconcile（含刪除圖譜已
  無對應實體的殘檔——只碰 export 目錄第一層 .md，該目錄整個是生成物）。
- **防迴圈**：`md.yaml` 新欄位 `export_dir`（預設 "entities"）+ `export_notes`（*bool，
  未設=啟用）；worker 的 FullScan（SkipDir）/watchLoop（事件過濾）/addRecursive（不掛 watch）
  三處都排除 export 目錄——否則鏡像檔會被當筆記再攝取（sanitize 過的檔名會生重複實體）。
- **GraphBackend 介面加 `ListEntities`/`ListRelations`**（Kùzu 實作：`MATCH (n:Entity) RETURN n` /
  `MATCH (a)-[r]->(b) RETURN a.name, b.name, r.type`）。ListRelations 拿真實方向——
  GetLocalContext 的無向遍歷把 center 一律當 Source，方向不可信，鏡像需要真方向。

### (2) Vault 下載鏈路：agent_graph VaultManifest/VaultFetch → gateway 轉發 → pub_client Sync Vault

- **agent_graph**：`vault_files.go` 的 `VaultFS`（唯讀層）——Manifest 列全 vault .md
  （跳過 dot 目錄，含 sha256）；Open 做路徑安全（絕對路徑/../非 .md 明確回錯）。
  proto 加 `VaultManifest` + `VaultFetch(stream VaultFileChunk)`——**全 repo 第一個
  server-streaming RPC**（既有 streaming 都是 client-streaming 上傳）。chunk ≤64KB，
  每檔尾隨 eof=true 空 chunk。
- **agent_gateway**：`client_gateway.proto` 鏡像兩個 RPC + `GraphEntity.degree`；
  forwarder `VaultFetch` = 下游 Recv → 上游 Send 邊收邊轉（UploadIngest 的相反方向）。
  stream auth interceptor 按 `/agent_gateway.v1.ClientGateway/` prefix 攔，新 RPC 自動涵蓋，
  interceptor 零改動。pb 重生後照慣例複製到 `pub_client/pb/gatewaypb/` 與 `rag_admin/pb/gatewaypb/`
  （rag_admin build 驗證過）；`pub_client/proto/client_gateway.proto` 文件性拷貝一併同步
  （順帶把先前已落後的 ChatStatus/ChatImage/Persona 段補齊了）。
- **pub_client**：`vault_sync.go` 的 `SyncVault()`——manifest → 本地 sha256 比對 → 只下載
  缺少/不同的檔（分批 ≤200 路徑/stream）→ `safeVaultLocalPath` 防 server 送逃逸路徑
  （**client 端也要防**：惡意/失控 gateway 不能寫出 vault 資料夾外）。單向 pull：本地多出
  的檔不動。`gateway_client.go` 加 `VaultManifest`/`FetchVaultFiles`（**第一個 receive-stream
  client 方法**，per-file buffer 到 eof 才交付）。Config 加 `VaultDir`（DuckDB 單 JSON blob，
  零遷移）；設定頁加 Vault Folder（資料夾選擇器抽成 `folderPickerRow` 與 Coding Workspace 共用）；
  Graph 分頁控制列加 **Sync Vault** 鈕（進度打 statusLabel；VaultDir 未設彈提示）。
  測試 `vault_sync_test.go`：全新下載/增量零下載/單檔變更/本地檔不動/逃逸路徑拒絕。

### (3) 搜尋關鍵節點 + degree

- **Entity/GraphEntity proto 加 `degree`**（=6）；facade 層統一回填（`degreeMap()` 從
  ListRelations 算全圖 degree，best-effort 失敗不弄壞主查詢）——SearchEntities/GetLocalContext/
  HybridSearch（seeds + 每個 context）都帶。
- **pub_client `keyNodeIndex()`**：rank = 相關性 ×（1 + ln(1+degree)）；語意搜尋用向量相似度、
  關鍵字搜尋（score=0）視為同分＝純比連結度。搜尋完自動 `resultList.Select(key)` → 觸發
  loadContext → 圖譜直接跳到關鍵節點鄰域；狀態列顯示 "key node: X (degree N)"。
- **graphWidget 節點半徑改用全圖 degree**（後端值 > 子圖 degree 時採用）——跟 Obsidian 一致，
  節點大小反映整個知識庫的引用數。
