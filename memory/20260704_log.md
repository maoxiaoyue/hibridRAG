## 6. 建立 agent_graph 微服務（A4 Knowledge Agent / Graph RAG）+ agent_client 知識圖譜分頁

延續之前對 Agentic+Graph RAG 混合架構的評估，使用者要求建立第 7 個微服務 `agent_graph`，規格：沿用 agent_critic 的 HTTP+gRPC+TLS 骨架；PG 連線到 **192.168.50.104:5432**（獨立於 agent_memory 用的 .201，AGE 對 PG 版本綁定緊，隔離風險）；LLM 固定寫在 `app/config/ollama.yaml`；Obsidian vault 路徑設定在 `app/config/md.yaml`；直接打 Ollama（跟 agents 的 SemanticMemory 一致，不經 agent_embedding）；agent_client 順便加知識圖譜瀏覽/查詢 UI；所有 DB 連線用 hidb。

**技術設計重點**（供未來參考）：
- **Apache AGE + pgvector 各自獨立、各自 best-effort**：EnsureAGESchema/EnsureVectorSchema 各自嘗試 `CREATE EXTENSION`，任一失敗只停用對應功能（比照 agent_memory 的 Cassandra 模式），不阻擋服務啟動。entity_embeddings 是普通 pgvector 表，不是圖節點屬性（agtype 沒有向量型別）。
- **Cypher 安全模式**：查詢文字永遠是 Go 常數字串，動態值一律經 params（JSON 編碼綁定單一 SQL 參數）傳入；唯一例外是 hop 數（Cypher 不支援參數化路徑長度），用 clamp 過的 int 做 `%d` 格式化。所有節點統一 `:Entity` 標籤、邊統一 `:RELATES_TO`，語意差異放屬性（`category`/`type`），側步 Cypher 無法參數化 label 名稱的限制。
- **連線池 + AGE**：AGE 的 `cypher()` 需要每個 PG 連線各自 `LOAD 'age'` + `SET search_path`——用 `bun.DB.Conn(ctx)` 拿釘住的連線依序執行，而不是對池裡任意連線下指令（bun.Conn 是 v1.2.17 才有的功能，`db.format(query,args)` 用 bun 自己的 `?` placeholder 格式化並轉義成字面量，不是走 driver 原生 bind — 這代表 bun.DB/bun.Conn 的 ExecContext/QueryContext 都能直接用 `?` 佔位）。
- **agtype 解析**：JSON body + 選擇性 `::vertex`/`::edge`/`::path` 後綴，用固定允許清單比對後綴（不能「找最後一個 :: 就切」，會誤切含 `::` 的純量字串）。
- **proto 生成踩坑**（跟上次 agent_critic 一樣但這次還多一個）：`google/protobuf/struct.proto` 需要 `-I "D:\GoProjects\bin\protoc\include"` 額外 include path 才找得到 well-known types；graph name 用 M-mapping `-Magent_graph/proto/graph.proto=pb/graphpb` 生成到正確位置。

**Obsidian 同步 worker**：全量掃描 + fsnotify（需手動 walk 加所有子目錄，fsnotify 不支援遞迴）+ debounce。WikiLink（`[[Page]]`）→ 確定性、直接 MERGE；LLM 抽取的關係 → confidence >= threshold（預設 0.75）才自動 MERGE，否則進 `proposed_relations` 待審——對應之前討論的「主動式知識整理」高信心自動/低信心待審護欄設計。

**單元測試**（23+ 個，DB/AGE/Ollama 全部走 disabled-path 或純邏輯測試）：agtype 解析（含含 `::` 的純量字串不誤切）、markdown frontmatter/WikiLink 解析（含畸形 frontmatter 容錯、圖片 embed 過濾）、pgvector 格式化、confidence threshold 預設值、GraphClient 對 httptest 真實 HTTP round-trip。

**未能驗證**（誠實記錄，環境限制非程式碼問題）：`192.168.50.104:5432`（PG）與 `:11434`（Ollama）從這個沙箱連不到（.201 那組連得到，.104 本機對其他 port 有回應但這兩個 port 連不上）——`go run .` 確認了乾淨的失敗行為（清楚錯誤訊息 + 正常 exit，不 hang 不 panic），但無法驗證 AGE extension 真的能裝、create_graph 語法版本相容性、真實 Cypher round-trip、真實 Ollama 呼叫、真實 vault 同步。已在 agent_graph/CLAUDE.md 誠實記錄「已驗證 vs 未驗證」兩節，並建議部署前在能連到 .104 的環境跑一次確認三個 ready log。
