## 三、實作 `internal/agent/persona/parser.go`

### 原因
架構圖 ① 明確標示 `internal/agent/persona.go` 為 SKILL.md 結構解析器，但整個專案不存在此檔。現有的 `skill_loader.go` 只做文字讀取與快取，不做結構化解析。PersonalMemory / ProceduralMemory 無法從 SKILL.md 自動填入。

### 設計決策

**為什麼建 package 而非單一 `internal/agent/persona.go`？**
沿用 `internal/agent/<topic>/` 的目錄慣例（`embed/`、`ingest/`、`vectordb/`），建立 `internal/agent/persona/` 套件，更易於之後加測試和子模組。

**SKILL.md 格式設計**
採用 Markdown H2/H3 分段，每段有對應的資料型別：
```
## Identity           → PersonalMemory.Identity (map)
## Expression DNA     → PersonalMemory.ExpressionDNA (map)
## Mental Models
### Model Name        → ProceduralMemory.ModelName
Content...            → ProceduralMemory.Content
**Heuristics**
- key: value          → ProceduralMemory.Heuristics (map)
```
同時支援中文 section 標題（`身份卡`、`表達 DNA`、`心智模型`、`決策啟發式`）。

**為什麼 `Parse()` 是純函式（無副作用）？**
解析與寫入分離，讓 runner 控制是否/何時寫入 DB。便於測試（不需 DB 連線即可測解析邏輯）。

**`ToPersonalMemoryRequest()` 回傳 nil 的設計**
若 Identity 和 ExpressionDNA 皆為空，回傳 nil，讓 runner 跳過寫入，避免寫入空資料。H1 的 agent 名稱若 Identity 中未設 `name`，自動填入作為 fallback。

### 實作細節
- 正規表達式切分 H2/H3 section
- `parseKVSection()` 支援 bullet (`- key: value`) 與 plain (`key: value`) 兩種格式
- `parseMentalModelBody()` 以 `**Heuristics**`（中英文）為切分點
- `normalizeKey()` 將 key 轉 snake_case

## 四、實作 `internal/agent/ingest/runner.go`

### 原因
`IngestService.EnqueueSkill()` 呼叫 `runner.RunSkill()`，但 `runner` 欄位為 `nil`（`dispatchSkill` 中 `if s.runner == nil { return }`），導致 SKILL.md 攝取任務建立後什麼都不做。需要實作 `IngestRunner` 介面的具體結構。

### MemoryService 擴充：UpsertPersonal / UpsertProcedural

**為什麼需要 Upsert 而非 Create？**
`RunSkill` 必須是冪等的——同一個 `agent_id` 重複 ingest SKILL.md 不應產生重複記錄。

**UpsertPersonal 策略**
`personal_memory` 有 `UNIQUE INDEX uq_personal_memory_agent(agent_id)`，直接用：
```sql
INSERT ... ON CONFLICT (agent_id) DO UPDATE SET identity=EXCLUDED.identity, ...
```
衝突時覆寫，回傳實際落地 row（需再 SELECT 一次，因 INSERT 的 ID 在 conflict 時是舊 row 的 ID）。

**UpsertProcedural 策略**
`procedural_memory` 的 `(agent_id, model_name)` 是普通 index，非 unique constraint，無法用 `ON CONFLICT`。改用 SELECT-then-insert/update：
1. SELECT WHERE agent_id=? AND model_name=?
2. 若找到 → UPDATE content/heuristics/updated_at
3. 若 ErrNoRows → INSERT 新記錄

### MemoryWriter 介面設計

**為什麼在 runner 套件定義介面，而非直接依賴 MemoryService？**
`internal/agent/ingest` 依賴 `app/services` 會形成跨層耦合。定義最小介面讓 runner 只看到它需要的兩個方法，測試時注入 mock 而無需 DB 連線。`app/services.MemoryService` 自然滿足該介面。

### Runner 設計

**RunSkill 流程**
```
os.ReadFile(req.SkillPath)
→ persona.Parse()
→ IsEmpty() 檢查（空檔案回 error，不寫 DB）
→ UpsertPersonal（若有 Identity/ExpressionDNA）
→ UpsertProcedural × N（每個 MentalModel 一筆）
→ job.TotalChunks / DoneChunks 逐步更新
```

**RunReferences**
需要 embed client + vectordb，屬 Phase 2。目前回傳明確 error 並填 `job.TotalChunks = len(req.Paths)`，讓 IngestService 把 job 標記為 failed（語意正確——功能尚未實作）。

**進度追蹤**
直接修改 `job` struct 的欄位，由 `IngestService.markDone()` 統一寫回 DB，runner 不需要 DB 連線。

### 測試結果（7 cases，全 PASS）
```
TestRunSkill_Full                PASS  (1 personal + 2 procedural, TotalChunks=3)
TestRunSkill_NoMentalModels      PASS  (只有 personal)
TestRunSkill_FileNotFound        PASS  (os.ReadFile error)
TestRunSkill_EmptyFile           PASS  (IsEmpty() error)
TestRunSkill_PersonalError       PASS  (UpsertPersonal 回 error)
TestRunSkill_ProceduralError     PASS  (UpsertProcedural 回 error)
TestRunReferences_NotImplemented PASS  (not implemented error + TotalChunks)
```
