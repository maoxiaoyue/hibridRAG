## 關鍵決策 / 踩坑（未來的我需要知道的）

1. **proto 撞名**：agents 的 proto 生成到 `app/models`（跟手寫 DTO 同 package）——新訊息 `ClientToolSpec/ClientToolCall/ClientToolResult/ChatUsage` 與 chat.go 手寫型別重名，編譯才炸。改 proto 訊息名為 `ChatToolSpec/ChatToolCall/ChatToolResult/TokenUsage`。**教訓：往 `agent.proto` 加訊息前先 grep `app/models` 手寫型別**。

2. **mtls 套件是 5 份相同拷貝**（agents/memory/critic/graph/gateway 的 `internal/mtls/mtls.go`），沿用 vector_marshal 的複製慣例。改一份要同步五份。

3. **mTLS 開關語意**：`mtlsOn = server.tls.enabled && grpc.ca_file != ""`——ca_file 設了但 TLS 沒開時 interceptor 會拒絕全部（PeerCN 取不到），這是「安全預設」不是 bug。dev 全部留空 = 舊行為完全不變。

4. **client TLS 語意變更**：各 client 的 `ca_file` 設定後 `insecure_skip_verify` 失效（改做完整驗證）；都空 + insecure=false 時走系統根憑證（正式 CA 用）。

5. **TOFU 原子綁定**：`UPDATE ... WHERE key_hash=? AND (device_id IS NULL OR device_id='')`，RowsAffected=0 時重查比對（競態輸了但可能是同裝置 double-fire）。`last_used_at` 更新丟 goroutine best-effort。

6. **gateway 對內 dial 全部非阻塞**（`grpc.NewClient`）：下游沒起來不擋 gateway 啟動，呼叫時自然回 Unavailable——跟 agents 對 memory 的「硬依賴 exit」刻意不同。

7. **agent_client 介面對齊策略**：`GatewayClient` 提供與舊三個 REST client 完全相同的方法簽名（Chat/Upload/GetJob/SearchEntities/.../SearchCount），views 只把 `st.Client/GraphClient/EmbClient` 換成 `st.Gateway`，零邏輯改動。`ChatEngine` 改吃 `ChatBackend` 介面，engine 測試改用 stub（原 httptest 測試隨 REST client 一起刪）。

8. **device_id**：`SHA-256(MachineGuid + "|" + username)`（`golang.org/x/sys/windows/registry`）；取不到退回隨機 id 存 config.json。x/sys 本來就是 Fyne 的 indirect dep。

9. **憑證出 git**：`*/certs/` 與 `certs-internal/` 加 .gitignore 並 `git rm --cached`（14 個檔案）——外網分支不能帶私鑰。部署機用新版 gencert 重新產生即可。

10. **agent_client go.mod**：新增 grpc/protobuf 直接依賴（先前只有 Fyne/hypgo），`go mod tidy` 會拉 otel 等 transitive——build 時間變長屬預期。

## 補充輪（同日稍晚）：三個被忽略的需求

1. **信任內網通道（dev_090 相容）**：`mtls` 套件加 `PeerIPTrusted`（IP/CIDR）+ `ServerCredentials` 的 `allowNoClientCert` 參數。**關鍵細節**：mTLS 開啟時 `RequireAndVerifyClientCert` 在 TLS 握手就擋掉沒憑證的呼叫端，interceptor 根本輪不到判 IP——所以有設 `trusted_ips` 時握手要降為 `VerifyClientCertIfGiven`（有憑證就驗、沒憑證放進來給 interceptor 判「CN 或信任 IP」）。gateway 的 auth interceptor 同樣加 `auth.trusted_ips` bypass（命中時 KeyName 顯示 "(trusted internal IP)"）。不設 trusted_ips = 行為與之前完全相同（最嚴模式）。5 份 mtls 拷貝同步 + 5 個 config.yaml 補欄位。
2. **外網唯一入口**：程式碼面已有（API Key 強制 + 內部服務綁內網），本輪補 deploy README 的防火牆規則（`deny incoming` + 內網段放行 + 只開 9090）。

## 實作輪三：外網 client 改名 pub_client + DuckDB 加密儲存（同日）

1. **改名**：`git mv agent_client pub_client` + module/import 全改寫（23 檔）。外部引用（deploy README、gateway proto 註解、根 CLAUDE.md 目錄表）同步。
2. **DuckDB 加密儲存**（`app/store/store.go`，github.com/marcboeker/go-duckdb/v2 v2.4.3，bundled DuckDB 1.4.x）：
   - 單一加密檔 `%APPDATA%\pub_client\store.duckdb`：`settings`（config 整包 JSON）+ `chat_sessions`（session_id/agent_id/transcript/updated_at）
   - **加密方式**：in-memory 開庫 + `ATTACH '<path>' AS store (ENCRYPTION_KEY '<key>')`（DuckDB 內建 AES）；`SetMaxOpenConns(1)` 避開 ATTACH 連線範圍問題（桌面 app 單連線足夠）
   - **金鑰**：優先機器特徵（同 StableDeviceID 的 SHA-256(MachineGuid+username)，不落地）；fallback `store.key`（隨機、0600）——**避開雞生蛋問題**：fallback 隨機 device id 存在 config（在加密庫裡），所以加密金鑰不能依賴 config 內容
   - **遷移**：store 內無 config 時讀舊明文 `config.json`（pub_client/ 與 agent_client/ 兩個舊目錄名都查）→ 匯入後改名 `.imported`
   - 對話轉錄從 `sessions/*.md` 檔案改進 DB；History 鈕從「開資料夾」改成 session 瀏覽 dialog（清單 + Markdown 渲染檢視）；`transcript_service.go` 刪除
   - **測試 5 組全過**，關鍵兩個：錯誤金鑰 ATTACH 被拒（"Wrong encryption key"）、**store 檔案內掃不到明文 API Key**（加密有效性直接驗證）
3. 注意：go-duckdb 拉進多平台 prebuilt bindings（repo 體積/建置時間增加）；CGO 本來就開（Fyne）所以鏈結無礙。
