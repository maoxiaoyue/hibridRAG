## 一、agent_registry（新建服務）

### 功能
- Agent 自我註冊（heartbeat upsert）
- 依 ID 查詢、依技能 keyword 搜尋（JSONB GIN index）
- 支援 `grpc_endpoint` 欄位（今日後期加入）

### 重要決策

**為何用 Bun ORM + PostgreSQL 而非記憶體 map？**
Registry 重啟後資料不遺失；多個 gateway 實例可共用同一 registry。

**`grpc_endpoint` 與 `url` 分開設計**：
- `url` = A2A HTTP endpoint（`http://host:port/`）
- `grpc_endpoint` = gRPC dial address（`host:port`，不含 scheme）
- 空 `grpc_endpoint` 表示該 Agent 只支援 A2A HTTP

### 主要檔案

| 檔案 | 說明 |
|------|------|
| `app/models/registration.go` | `AgentRegistration` Bun 模型 + DTOs；`AutoMigrate()` |
| `app/services/registry_service.go` | Upsert / GetByID / Search（JSONB 子查詢） / Delete |
| `app/controllers/registry.go` | Register / GetAgent / SearchAgents / Deregister |
| `app/commands/root.go` | Cobra `serve` 子命令，啟動 HTTP server |
| `config/config.yaml` | addr `:8500`，DSN 指向 `192.168.50.201:5433/mcp` |

### API 端點

```
POST   /registry/register         # 注冊或更新 agent
GET    /registry/agents/:id       # 查詢單一 agent
GET    /registry/search?skill=    # 技能關鍵字搜尋
DELETE /registry/agents/:id       # 刪除
GET    /health
```

## 二、agent_gateway（從 stub 到完整服務）

### 架構

```
外部 Client
  ├── HTTP POST /          → A2A JSON-RPC dispatcher → registry → A2A HTTP 轉發
  ├── HTTP GET /.well-known/agent-card.json
  └── gRPC :9090           → AgentService/Inbound → registry → gRPC 轉發
```

### 重要決策

**雙協議設計**：
- A2A JSON-RPC（HTTP `:8090`）面向前端、外部服務、其他 A2A agent
- gRPC（`:9090`）面向內部服務（`agents/` 等使用 `GrpcDispatcher` 的服務）
- 兩個協議共用同一個 `RegistryClient`

**不引入 protoc**：
直接複製 `agents/app/models/agent.pb.go` 和 `agent_grpc.pb.go` 到 `agent_gateway/app/models/`。
兩者的 `package models` 宣告相同，標準 grpc/protobuf import 無模組依賴問題，不需重新生成。

**gRPC 路由策略**：
1. 先用 `payload.agent_id` 直接查 registry（`GET /registry/agents/:id`）
2. 找不到時 fallback：用 `agent_id` 當 skill keyword 搜尋
3. 取得 `grpc_endpoint` 後透過連線池轉發

**A2A 路由策略**：
- 從 `params.x-skill` 取技能提示，呼叫 `registry/search?skill=`
- 無 x-skill 時取 last_seen_at DESC 第一筆
- task_id 由 gateway 自動產生（若 client 未提供）

| 檔案 | 說明 |
|------|------|
| `app/models/a2a.go` | A2A 協議型別、JSON-RPC types、錯誤碼常數、RegistryAgent |

| `app/models/agent_grpc.pb.go` | 複製自 agents/（gRPC client/server 介面） |

### 錯誤碼（gRPC InboundAck.code）

| code | 意義 |
|------|------|
| 0 | 成功 |
| 400 | 請求缺欄位（nil payload / 空 messages / 缺 agent_id） |
| 502 | 下游 Agent 不可達或無 gRPC endpoint |

### 錯誤碼（A2A JSON-RPC error.code）

| code | 意義 |
|------|------|
| -32700 | Parse error |
| -32600 | Invalid Request |
| -32601 | Method Not Found |
| -32001 | 找不到符合技能的 Agent |
| -32002 | 下游 Agent 連線失敗 |

## 三、hidb API 修正

### 問題
`internal/db/init.go` 使用 `hidb.DatabaseConfigInterface`，但 hypgo 沒有從 `hidb` 套件直接 export 此型別。

### 修正歷程
1. 最初：`agent_memory` 改用 `hypconfig.DatabaseConfigInterface`（workaround）
2. 使用者指出 v0.8.5 已有更好的方式：`hidb.New(cfg any, ...)`
3. 最終設計：`Init(cfg any)` → `hidb.New(cfg, hidb.WithDialect(pg.New()))`
   - `hidb.New()` 內部先嘗試 type assert → 若 cfg 實作 interface 直接用；否則用 duck-typing adapter
   - `internal/db` 不再 import `hypconfig`，更乾淨

影響：`agent_memory/internal/db/init.go` + `agent_registry/internal/db/init.go`
