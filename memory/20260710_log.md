### 2. rag_admin Models 分頁：`List models FAIL — parse "192.168.50.104:8500/registry/models": first path segment in URL cannot contain colon`

**根因**：使用者在 Settings 分頁的 Registry URL 欄位只填了 `192.168.50.104:8500`（沒帶
`https://`）。`rag_admin/app/services/modeladmin_client.go`（`ListModels`）跟
`graphinput_client.go` 都是單純字串串接 `registryURL + "/registry/models"` 送進
`http.NewRequestWithContext`；Go 的 `url.Parse` 在沒有 scheme 時會把 `192.168.50.104` 誤判成
scheme，第一個路徑段含冒號就直接報錯——這是全 rag_admin 兩個直連 REST client（registry /
graphinput）共通的缺陷，程式碼完全沒有補 scheme 的防呆。

**修復**：`modeladmin_client.go` 新增 `normalizeHTTPBaseURL()`（缺 `://` 就補 `https://`；已有
scheme 原樣保留），套用到 `NewModelAdminClient`（registryURL + agentsURL 兩個參數）與
`NewGraphInputClient`（同 package，直接共用）。

**順手抓到的第二個 bug**：`models_view.go` 的 `loadModels()` 在 `ListModels` 失敗時直接
`return`，導致 `loadPersonas()`（走完全獨立的 gRPC `ListPersonas`，跟 registry URL 無關）
永遠不會被呼叫——這解釋了使用者說「連 agent 設定都列不出來」，即使 persona 那條路徑本身是通的。
改成失敗也要呼叫 `loadPersonas()`，兩個資料來源解耦。

`go build`/`go vet`/`go test` 全綠。
