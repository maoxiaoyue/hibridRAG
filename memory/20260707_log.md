## 一、agent_client / pub_client 中文顯示修復（編碼假象，實為缺字）

**現象**：對話框打中文顯示成 □/�（截圖 `You: ������`），ASCII 分頁標題正常。

**根因**：不是編碼錯誤，是 Fyne v2.4.5 內建字型無 CJK 字形。且 Fyne 的文字渲染走
go-text `font.ParseTTF`——**不支援 .ttc 集合**（msjh.ttc / msyh.ttc / mingliu.ttc 皆解析失敗），
只能用純 TTF。實測 `NotoSansTC-VF.ttf`、`simhei.ttf`、`kaiu.ttf` 三個純 TTF 都能被 ParseTTF 解析。

**修法**：兩個 client 各新增 `app/views/theme.go`：`cjkTheme` 包住內建主題，把非等寬/非符號
文字字型換成系統 CJK 純 TTF（候選序 NotoSansTC-VF → simhei → kaiu，取第一個存在的；可用
`FYNE_FONT` 覆寫）。`main_view.go` 於 `app.New()` 後 `applyCJKFont(a)`。等寬/符號維持內建以
保留程式碼區塊與 icon。找不到字型時只印 warning 不中斷。

（截圖那個 `dial tcp 127.0.0.1:9090 connection refused` 是 gateway 未啟動，與字型無關，未動。）

## 三、對話狀態列顯示「目前哪個 Agent 在處理」（取代只跳秒數）

需求：兩個 client 的 Think 指示器目前只有秒數在跳；改為顯示「目前由哪一個 Agent 正在處理」，
狀態經 agent_gateway 回傳，顯示在秒數前。

**決策（AskUserQuestion）**：「哪個 Agent」= 混合 RAG 的階段 Agent 1-4（Agent1 ContextBuilder /
Agent2 ToolLoop / Agent3 Critic / Agent4 Graph；Critic 只在 gRPC Inbound 路徑跑，`/api/chat` 不經過，
故 client 對話實際看到 Agent 1/2/4）；傳輸 = **每秒輪詢狀態端點**（不改 Chat unary 語意）。

**機制**：Chat 是 unary，子階段全在 agents 內部同一 blocking call 跑，gateway 只是管道。故 agents 用
in-memory tracker 記目前階段 + 開 HTTP 端點；gateway 加 ChatStatus RPC 內部 HTTP 問 agents；client
每秒經 gateway 輪詢。

- **agents**：`app/services/chat_status.go`（`ChatStatusTracker`：session→stage，RWMutex，5min TTL，
  容忍 nil receiver）。`AgentServer.WithStatus` 注入。ChatSync 進場設 `StageContextBuilder`（sessionID
  解析上移到 ctxBuilder 前）；runChatLoop 每輪設 `StageToolLoop`、graph_query 工具設 `StageGraph`、
  離場 defer Clear。HTTP `GET /api/chat/status/:session_id`（`controllers/chat_status.go`）。
- **gateway**：`client_gateway.proto` 加 `rpc ChatStatus`；用 `D:/GoProjects/bin/protoc.exe`
  （`module=agent_gatway`）重生 `pb/gatewaypb`，複製到兩 client。轉發走內部 HTTP 打 agents
  （reuse s.httpClient）；config 加 `internal.agents_http_base`（`https://localhost:18080`）。
  輪詢失敗一律回空狀態，不擾動對話。
- **兩 client**：`GatewayClient.ChatStatus`；`ChatEngine` 加 `preferredSessionID` +
  `SetPreferredSessionID`（新對話首輪帶 client 產生的 session id，讓輪詢首輪就有 key；**不動**
  AGENTS.md 首輪注入的 `e.sessionID==""` 判斷）+ `NewSessionID()`；chat_view 首輪產生 session id，
  ticker 每秒 `gateway.ChatStatus(sessionID)`，active 時把 stage 寫進 phase（顯示在秒數前，例
  `Agent 2 · ToolLoop (3s)`），非 active（等本地工具）維持本地階段。

四 module build+vet+test 全綠。**待內網驗證**：真對話階段切換的即時觀感、每秒一次 gRPC 往返負擔。

## 四、對話附加圖片，讓 RAG/agent 辨識

需求：在 chat 或程式設計時可附加圖片檔案，讓 agent 辨識。

**決策（AskUserQuestion）**：圖片處理 = **視覺模型 OCR/描述成文字**後當 context（reuse 現有
VisionExtractor，任何對話模型都適用）；附圖 = **當下對話 + 同時 ingest 進 RAG**。

**設計取捨**：Chat 是 unary，若把圖片 bytes 穿進 Chat/continuation 要動 gateway + agents 兩個
proto。改用**獨立一步**：新 gateway `ChatImage` RPC → agents HTTP 端點抽文字（+ingest），回傳文字，
client 把文字**併進該輪訊息**再走原本的 Chat。→ 只動 gateway proto，agents proto 不動，Chat/
continuation 不動。

- **agents**：`app/controllers/chat_image.go` 的 `POST /api/chat/image?agent_id=&filename=`
  （body=原始圖片 bytes）：落地 → `extractToText`（圖片走 VisionExtractor）→ 讀回文字 →
  `EnqueueReferences`（tag `chat-image`，best-effort ingest）→ 回 `{text, chars}`。重用 ingest_upload
  的既有 helper（uploadsDirFor / extractToText / sanitizeName / randPrefix）。
- **gateway**：`client_gateway.proto` 加 `rpc ChatImage(ChatImageReq{agent_id,filename,bytes image})
  returns (ChatImageResp{text})`；重生 pb 複製到兩 client。轉發走內部 HTTP POST 原始 bytes 到 agents
  `/api/chat/image`（專屬 120s client，reuse TLS transport；vision 較久）。
- **兩 client**：`GatewayClient.ChatImage`；chat_view 加「Attach Image」鈕（FileOpen + 副檔名 filter）
  + attachedImages 狀態 + attachLabel；send 時擷取並清空附圖，goroutine 內逐張 `ChatImage` 抽文字，
  以 `[附加圖片: name]\n<text>\n\n` 前綴併進 `sentText`（顯示給使用者的 `**You:**` 只加 `(附加圖片: …)`
  註記，不塞辨識文字）；允許「只有圖片、無文字」也能送。

四 module build+vet+test 全綠。**待內網驗證**：需 agents `ingest.vision.enabled=true`（未設時端點回
422、client 顯示 recognition failed）；真圖片 → 視覺模型抽文字品質 + ingest 落庫。
