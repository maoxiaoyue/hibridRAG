# 2026-07-12 工作日誌

## Ollama/GPU 使用狀況監控（agents，使用者三點需求）

需求：(1) 建立監控 Ollama 與 GPU 使用狀況的機制；(2) Agent 1-4 使用前先確認 GPU 狀況；
(3) goroutine 空閒時每 10 分鐘觀測。前置盤點（前一輪對話）已確認：全平台原本零 GPU 監控、
`agents` 是唯一真正打 Ollama 推理的服務（gateway 純轉發、registry 只查 metadata）。

### 關鍵設計決策：GPU 在遠端，觀測分兩條腿

GPU 在 Ollama 主機（`.104`/`.201`）上，`agents` 不一定同機——不能假設本機 `nvidia-smi`
看得到目標 GPU。因此：

1. **Ollama `/api/ps`（遠端可用，主力）**：回報每個 host 已載入的模型與 `size_vram`。
   額外紅利：`size_vram < size` = 模型部分溢出到 CPU RAM——VRAM 不足的典型徵兆，
   推理會顯著變慢，轉成明確 warning（這是遠端唯一能拿到的「GPU 壓力」訊號）。
2. **本機 `nvidia-smi`（best-effort）**：`exec.LookPath` 找得到才啟用（同機部署場景）；
   `--query-gpu=index,name,utilization.gpu,memory.used,memory.total,temperature.gpu
   --format=csv,noheader,nounits` 解析，util/VRAM 超門檻記 warning。

### 實作（全部在 agents/）

- **`app/services/gpu_monitor.go`**：`GPUMonitor`——`Sample()`（打全部 host 的 /api/ps +
  可選 nvidia-smi，warning 記進 snapshot + log）、`Last()` 快取、
  `CheckBeforeInference()`（快取 < stale_after(30s) 直接回快取，過期才重取樣（3s timeout），
  **只記 warning 永不擋推理**——GPU 忙不該讓對話失敗，慢總比錯好）、
  `Run(ctx)`（ticker 每 idle_interval(10min) 醒來，**若期間推理路徑已取樣過就跳過**——
  這就是「空閒時才觀測」的語意：忙碌期由推理前檢查覆蓋，ticker 只補空窗）。
  方法全部容忍 nil receiver（未接線 no-op，AgentServer 可選依賴慣例）。
- **推理前檢查（需求 2）**：`AgentServer.WithGPUMonitor` + 兩個進場點——
  `runChatLoop`（/api/chat 路徑，`agent_chat.go`）與 `process()`（gRPC Inbound 路徑，
  `agent_grpc.go`）開頭呼叫 `CheckBeforeInference`。放在管線起點 = Agent 1-4
  （ContextBuilder/ToolLoop/Critic/Graph）使用前。
- **REST `GET /api/monitor/gpu`**（`app/controllers/monitor.go`）：回最近快照，
  `?refresh=1` 強制重取樣；監控未啟用回 503。
- **config**：`config.go` 新 `MonitoringConfig{GPU GPUMonitorConfig}`（映射 yaml 既有的
  scaffold `monitoring:` 段，只取新的 `gpu:` 子段）；config.yaml 補 `monitoring.gpu`
  （enabled/ollama_urls/idle_interval_sec/stale_after_sec/nvidia_smi/util_warn_percent/
  vram_warn_percent）。`ollama_urls` 空 → 用 llm.yaml 的 chat Ollama URL（= `.104`）。
  **使用者明確指示：`.201`（BGE-M3 embedding 專用）不用監控**——觀測清單刻意不含它，
  監控只跟著推理負載走，config 註解已載明。
- **main.go**：llm client 建好後組 URL 清單 → `NewGPUMonitor` → `go gpuMon.Run(monCtx)`
  （`context.WithCancel` + defer cancel）→ `controllers.SetGPUMonitor` +
  `agentSrv.WithGPUMonitor`；route 註冊在 /metrics 旁。
