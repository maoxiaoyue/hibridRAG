## 後端（agents :18080）新增
- **`POST /api/chat`**（同步對話 + client 端工具回合制）。為何新增：既有 gRPC `Inbound`（`agent_grpc.go`）是 fire-and-forget、回覆 dispatch 到下游 gRPC，desktop client 收不到回覆。新端點同步回傳。
  - 檔案：`app/models/chat.go`（DTO，client tool schema 用 `json.RawMessage` 避免 import cycle）、`app/controllers/agent_chat.go`（`ChatSync` + 可暫停工具迴圈 + 記憶體 continuation store + `SetChatServer`）。
  - 機制：server 內建工具就地執行；LLM 呼叫到 **client 工具** → 回 `status=tool_calls`+`continuation_id`，client 本地執行後帶 `tool_results` resume → 直到 `final`。
  - 限制：continuation 存記憶體 map（K8s 多副本需改 Redis）；只在 LLM 支援 `ToolCallerLLM`（目前 Ollama）時有工具，否則退回純 Chat。復用 `loadPersona`/`ContextBuilder`/`writeEpisodic`。
- **`POST /api/ingest/upload`**（multipart）。檔案：`app/controllers/ingest_upload.go`、`app/services/vision_extractor.go`、config 加 `ingest.{uploads_dir,vision.*}`。
  - 流程：存檔 → PDF 用 `github.com/ledongthuc/pdf` 抽文字、圖片用 Ollama 視覺模型（`VisionExtractor`）抽文字 → 寫 .txt sidecar → 複用既有 `EnqueueReferences`（chunk→embed→Cassandra）。掃描型 PDF 不 OCR。

## 重要 bug 修正（多輪 tool 對話）
原本把 assistant 的 tool_calls 用佔位文字（"[tool_calls xN]"）塞進 ChatMessage.Content，resume 時 **gemma4 會忽略 tool result 甚至幻覺**（實測：問時間卻回 "10:35 AM PST"）。
修法：`services.EncodeAssistantToolCalls` 把 tool_calls 以 `[assistant_tool_calls]<json>` marker 編碼，`convertChatMessagesToOllama`（`llm_ollama_tools.go`）還原成 Ollama **原生 assistant.tool_calls**（content 清空）。修後 resume 正確使用 tool result。迴歸測試 `ollama_toolcalls_test.go`。此為 additive，不影響舊 RunToolLoop 路徑（它仍用 "[tool_calls xN]"，但 gRPC 多輪 client 工具不走它）。
